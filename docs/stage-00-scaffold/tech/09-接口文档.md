# 09 · 接口文档（OpenAPI）

> 对应源码：`config/OpenApiConfig.java`
> 配套配置：`application.yml` 的 `springdoc` 段、`pom.xml` 的 `springdoc-openapi-starter-webmvc-ui` 依赖

## 一、一句话定位

声明接口文档的**元信息**（标题、版本、认证方式），让 Swagger UI 有内容可展示。

真正的接口清单不是手写的——**SpringDoc 在运行时扫描所有 `@RestController` 自动生成**。这个类只负责「文档的门面」和「认证配置」。

## 二、完整代码

### OpenApiConfig.java

```java
@Configuration
public class OpenApiConfig {

    private static final String BEARER_AUTH = "bearerAuth";

    @Bean
    public OpenAPI canvasOpenApi() {
        return new OpenAPI()
                .info(new Info()
                        .title("无限画布后端 API")
                        .version("0.0.1")
                        .description("画布项目、素材库、提示词库、生成任务与对话助手的后端接口"))
                .components(new Components().addSecuritySchemes(BEARER_AUTH, new SecurityScheme()
                        .type(SecurityScheme.Type.HTTP)
                        .scheme("bearer")
                        .bearerFormat("JWT")
                        .description("登录后拿到的 accessToken，格式：Bearer {token}")));
    }
}
```

### 配套配置

```yaml
springdoc:
  swagger-ui:
    path: /swagger-ui.html
    tags-sorter: alpha        # 标签按字母排序
    operations-sorter: alpha  # 接口按字母排序
  api-docs:
    path: /v3/api-docs
```

## 三、逐段拆解

### 3.1 OpenAPI 3 和 Swagger 2 的关系

这两个名字经常混着叫，实际是**规范和工具**的关系：

| | OpenAPI | Swagger |
| --- | --- | --- |
| 是什么 | **规范**（描述 REST API 的 JSON/YAML 格式） | 一套**工具集**（编辑、UI、代码生成） |
| 版本 | 3.0 / 3.1（2021 年后由 Linux 基金会维护） | Swagger 2.0 是旧规范，已被 OpenAPI 3 取代 |
| 本项目 | OpenAPI 3（SpringDoc 生成） | Swagger UI 只是个**前端页面**，用来渲染 OpenAPI 文档 |

**现在的正确叫法**：规范叫 OpenAPI 3，UI 叫 Swagger UI。说「我们用 Swagger」也没错，但面试时说「OpenAPI 3 规范 + Swagger UI 渲染」更准确。

### 3.2 为什么用 SpringDoc 而不是 SpringFox

这是 **Spring Boot 3 的一个硬性约束**，值得单独说。

| | SpringFox | **SpringDoc**（当前） |
| --- | --- | --- |
| 最新版本活跃度 | **2020 年后基本停更** | 持续维护 |
| Spring Boot 3 支持 | ❌ **不兼容**（依赖 `javax.servlet`，Boot 3 是 `jakarta.servlet`） | ✅ 原生支持 |
| OpenAPI 版本 | 2.0 为主 | 3.0 |
| 集成方式 | `@EnableSwagger2` + `Docket` | **零配置**，自动扫描 |

**SpringFox 在 Boot 3 下的典型报错**：

```
java.lang.NoClassDefFoundError: javax/servlet/http/HttpServletRequest
```

或者启动直接失败，说找不到 `springfox.documentation.spring.web.plugins.Docket`。

**根因**：Spring Boot 3 把 `javax.*` 全迁到了 `jakarta.*`。SpringFox 最后发布版本（3.0.0，2020 年）还停留在 `javax`。

**所以选 SpringDoc 不是偏好问题，是唯一可行的选择。**

### 3.3 `Info` 里的三个字段

```java
.info(new Info()
        .title("无限画布后端 API")
        .version("0.0.1")
        .description("画布项目、素材库、提示词库、生成任务与对话助手的后端接口"))
```

| 字段 | 作用 | 建议 |
| --- | --- | --- |
| `title` | 文档标题，显示在 Swagger UI 顶部 | 写清楚是哪个服务 |
| `version` | API 版本 | **和 `pom.xml` 的 `<version>` 保持一致**，否则对接方会困惑 |
| `description` | 概述 | 一句话说清业务域 |

**`version` 的维护成本**：目前硬编码 `0.0.1`。更好的做法是从配置读：

```java
@Value("${app.version:unknown}")
private String version;
```

`application.yml` 里已经有 `app.version: 0.0.1` 了（`HealthService` 在用），改成读配置就能一处维护两处生效。阶段 1 可以顺手优化。

### 3.4 `SecurityScheme` 是干什么的

```java
.components(new Components().addSecuritySchemes(BEARER_AUTH, new SecurityScheme()
        .type(SecurityScheme.Type.HTTP)
        .scheme("bearer")
        .bearerFormat("JWT")
        .description("登录后拿到的 accessToken，格式：Bearer {token}")))
```

**它只是「声明」，不会产生任何实际效果**——阶段 0 没有认证，这段配置现在不影响任何请求。

**它的价值在阶段 1 之后**：Swagger UI 右上角会出现一个 🔒 **Authorize** 按钮，点开输入 token，之后所有请求自动带上 `Authorization: Bearer {token}`。

| 参数 | 值 | 含义 |
| --- | --- | --- |
| `type` | `HTTP` | HTTP 认证（区别于 `APIKEY`、`OAUTH2`、`OPENIDCONNECT`） |
| `scheme` | `bearer` | Bearer Token 方式 |
| `bearerFormat` | `JWT` | **纯提示性**，告诉使用者 token 长什么样，不影响行为 |

**为什么 `bearerFormat` 写了 `JWT` 却不校验**：OpenAPI 规范里它就是个文档字段，没有任何校验能力。真正的校验在后端过滤器里。

**`BEARER_AUTH` 这个常量**：定义成 `private static final` 是为了后面在 `@SecurityRequirement(name = "bearerAuth")` 里引用，避免拼错。

### 3.5 接口上的注解（阶段 1 开始用）

`HealthController` 已经用了两个：

```java
@Tag(name = "系统")
@RestController
@RequestMapping(ApiPath.V1 + "/health")
public class HealthController {

    @Operation(summary = "健康检查", description = "依次探测 MySQL 与 Redis，并返回各自耗时")
    @GetMapping
    public Result<HealthVO> health() { ... }
}
```

| 注解 | 用在哪 | 作用 |
| --- | --- | --- |
| `@Tag` | 类上 | 分组，Swagger UI 左侧的折叠菜单 |
| `@Operation` | 方法上 | 接口的摘要和详细说明 |
| `@Parameter` | 方法参数上 | 参数说明（`@RequestParam` 场景） |
| `@Schema` | 类 / 字段上 | DTO 的字段说明、示例值、是否必填 |
| `@ApiResponse` | 方法上 | 响应码和说明 |

**一个实用技巧**：`@Schema` 可以给字段加示例值，Swagger UI 里点「Try it out」会自动填充：

```java
public record CreateCanvasDTO(
    @Schema(description = "画布名称", example = "我的第一张画布", maxLength = 50)
    @NotBlank(message = "画布名称不能为空")
    String title
) {}
```

**注意**：`@Schema` 和 Jakarta Validation 的注解（`@NotBlank`）是**两套系统**，要分别写。前者只是文档，后者才真正校验。

### 3.6 `tags-sorter: alpha` 和 `operations-sorter: alpha`

```yaml
springdoc:
  swagger-ui:
    tags-sorter: alpha        # 左侧标签按字母序
    operations-sorter: alpha  # 组内接口按字母序
```

**默认行为**：按代码里声明的顺序（反射扫描的顺序，实际上很不稳定）。

**配 `alpha` 之后**：每次打开看到的顺序都一样，找接口不用来回翻。

**另一个可选值 `method`**：按 HTTP 方法排序（GET → POST → PUT → DELETE）。阶段 2 接口多了之后，`method` 可能更符合阅读习惯，到时可以换。

### 3.7 两个访问地址

```
Swagger UI：  http://127.0.0.1:8081/api/swagger-ui.html
OpenAPI JSON：http://127.0.0.1:8081/api/v3/api-docs
```

**注意 `/api` 前缀**：`application.yml` 里配了 `server.servlet.context-path: /api`，所以所有路径都要带这个前缀。

**这是实测踩过的坑**：第一次打开 `http://127.0.0.1:8081/swagger-ui.html` 返回 404，因为漏了 `/api`。

**`/v3/api-docs` 有什么用**：

```bash
# 导出 OpenAPI JSON，可以导入 Apifox / Postman / YApi
curl -s http://127.0.0.1:8081/api/v3/api-docs > openapi.json
```

这个 JSON 才是**可移植的接口契约**——可以给前端团队导入到 Apifox，也可以在 CI 里做接口变更检测（对比两次导出的 diff，发现破坏性变更就报警）。

**面试可以讲**：「接口文档不是给人看的网页，是可机器消费的契约。`/v3/api-docs` 导出的 JSON 可以接 Apifox 做 Mock、接 CI 做兼容性检查。」

### 3.8 生产环境必须关掉

**风险**：Swagger UI 暴露了全部接口、参数结构、错误码。攻击者不用扫目录就知道你有什么接口、参数叫什么。

**关闭方式**：

```yaml
# application-prod.yml
springdoc:
  api-docs:
    enabled: false
  swagger-ui:
    enabled: false
```

**或者更细的控制**：保留 UI 但要求认证（阶段 1 之后可以做）：

```java
.requestMatchers("/swagger-ui/**", "/v3/api-docs/**").authenticated()
```

**本项目阶段 8 部署时**：生产 profile 里直接关掉。这是 OWASP 里明确的建议。

## 四、设计决策

| 决策 | 选择 | 理由 | 替代方案与代价 |
| --- | --- | --- | --- |
| 文档框架 | SpringDoc | Boot 3 下 SpringFox 不可用 | SpringFox——`javax` 不兼容 |
| 规范版本 | OpenAPI 3 | 当前标准 | Swagger 2——已过时 |
| 认证声明 | 预留 `bearerAuth` | 阶段 1 直接用 | 阶段 1 再加——改一次配置 |
| 排序 | `alpha` | 顺序稳定 | 默认——每次刷新顺序可能变 |
| 版本号 | 硬编码 `0.0.1` | 阶段 0 简化 | 读 `app.version`——一处维护（建议阶段 1 改） |
| 生产开关 | 未配 | 阶段 8 处理 | 现在就配——还没有 prod profile |
| 文档导出 | 支持 `/v3/api-docs` | 可接入 Apifox / CI | 只保留 UI——无法机器消费 |

## 五、面试考察点

### 基础题

**Q1：Spring Boot 3 为什么不能用 SpringFox？**

答题要点：
- Spring Boot 3 把 `javax.servlet` 迁到了 `jakarta.servlet`
- SpringFox 3.0.0（2020 年）仍是 `javax` 命名空间，且已停止维护
- 症状：`NoClassDefFoundError: javax/servlet/http/HttpServletRequest`
- 替代：SpringDoc（OpenAPI 3）

**Q2：OpenAPI 和 Swagger 是什么关系？**

答题要点：
- OpenAPI 是**规范**（描述 REST API 的 JSON/YAML 格式），当前 3.x
- Swagger 是**工具集**（UI、编辑器、代码生成），Swagger 2.0 是旧规范
- 本项目：SpringDoc 生成 OpenAPI 3 文档，Swagger UI 渲染展示

**Q3：怎么在生产环境关闭接口文档？**

答题要点：
- `springdoc.api-docs.enabled: false` + `springdoc.swagger-ui.enabled: false`
- 或保留但加认证拦截
- 风险：暴露接口清单和参数结构，方便攻击者构造请求

### 进阶题

**Q4：`@Schema` 和 `@NotBlank` 有什么区别？**

答题要点：
- `@Schema`：**只是文档**，写进 OpenAPI JSON，Swagger UI 显示，不做校验
- `@NotBlank`：Jakarta Validation 注解，`@Valid` 触发时真正校验
- 两者要同时写，缺了 `@Schema` 文档缺说明，缺了 `@NotBlank` 不校验

**Q5：`SecurityScheme` 配了之后，后端会自动校验 token 吗？**

答题要点：
- **不会**。它纯粹是文档声明，让 Swagger UI 提供 Authorize 按钮
- 真正的校验在 Spring Security 的过滤器里
- 所以阶段 0 配了这段，请求依然不鉴权

**Q6：`/v3/api-docs` 除了给 Swagger UI 用，还有什么价值？**

答题要点：
- 导入 Apifox / Postman / YApi 做 Mock 和联调
- CI 里做接口兼容性检测（对比前后两次导出的 diff）
- 生成前端 TypeScript 类型定义
- 作为「接口契约」纳入版本管理

### 陷阱题

**Q7：Swagger UI 打开 404，可能是什么原因？**

答题要点：
1. **漏了 context-path**（本项目最常见）：正确地址是 `/api/swagger-ui.html` 不是 `/swagger-ui.html`
2. `springdoc` 版本和 Spring Boot 版本不匹配
3. 被 Spring Security 拦截了（阶段 1 后会出现）
4. `springdoc.swagger-ui.enabled` 设成了 false

**Q8：`bearerFormat: JWT` 写了有什么实际作用？**

答题要点：
- **没有校验作用**，纯粹是文档提示
- OpenAPI 规范里它只是描述性字段
- 有人误以为写了就会校验 JWT 格式，这是错的

## 六、常见坑

| 坑 | 现象 | 原因 | 处理 |
| --- | --- | --- | --- |
| 访问漏了 `/api` | 404 | context-path 没带 | 用 `/api/swagger-ui.html` |
| 用 SpringFox | 启动报 `javax` 类找不到 | Boot 3 不兼容 | 换 SpringDoc |
| springdoc 版本不匹配 | UI 白屏 / 加载失败 | 版本和 Boot 没对齐 | 按官方兼容表选版本 |
| 生产没关文档 | 接口清单泄露 | 没配开关 | prod profile 关掉 |
| `@Schema` 当校验用 | 非法参数也能进 | 注解性质误解 | 补 `@NotBlank` 等 |
| 文档版本和 pom 不一致 | 对接方困惑 | 两处硬编码 | 读 `app.version` 配置 |
