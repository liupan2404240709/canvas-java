# 12 · 一次上传 + 一次建素材的完整链路

## 一、为什么要单独讲链路

面试里最常被问的不是"某个注解有什么用"，而是"**你说说这个接口从收到请求到返回，中间都发生了什么**"。能按顺序讲完，说明你真的写过；只会背概念，第二个追问就露馅。

## 二、上传：`POST /api/v1/files/upload`

```
浏览器                  Filter 链                 Controller            Service                    磁盘 / MySQL
  │                       │                         │                     │                          │
  ├─ multipart/form-data →│                         │                     │                          │
  │                       ├─ TraceIdFilter（生成 traceId，塞进 MDC）      │                          │
  │                       ├─ JwtAuthenticationFilter（解析 token，挂 LoginUser）                     │
  │                       ├─ Security 放行（已登录）                       │                          │
  │                       ├──────────────────────→ │                     │                          │
  │                       │                    @RequestPart MultipartFile │                          │
  │                       │                         ├─ currentUserId() ──→│                          │
  │                       │                         ├─ upload() ────────→│                          │
  │                       │                         │                     ├─ normalize(mime)        │
  │                       │                         │                     ├─ categoryOf → image     │
  │                       │                         │                     ├─ limit = 20MB           │
  │                       │                         │                     ├─ createTemp() ─────────→│ .tmp/upload-xxx.part
  │                       │                         │                     ├─ copyToTemp()           │
  │                       │                         │                     │   ├─ 64KB 循环读         │
  │                       │                         │                     │   ├─ total > 20MB? → 400 │
  │                       │                         │                     │   ├─ digest.update()     │
  │                       │                         │                     │   └─ out.write()  ──────→│
  │                       │                         │                     ├─ sha256 = hex(digest)    │
  │                       │                         │                     ├─ matchesMagic() → true  │
  │                       │                         │                     ├─ SELECT t_file(user,sha)│
  │                       │                         │                     │   └─ 命中 → 删 temp，返回 │
  │                       │                         │                     ├─ readSize(temp) → 320×240│
  │                       │                         │                     ├─ commit(temp, key) ────→│ move 到 ab/abcdef
  │                       │                         │                     ├─ INSERT t_file ────────→│
  │                       │                         │←─ FileVO ───────────┤                          │
  │←─ 200 {id,url,sha256,deduped:false} ────────────┤                     │                          │
```

**时间花在哪**（100KB 图片，本地实测量级）：

| 步骤 | 耗时 |
| --- | --- |
| 读 multipart 到临时文件（Tomcat） | ~1ms |
| copyToTemp + SHA-256 | ~1ms |
| SELECT 查秒传 | ~0.5ms |
| move（同盘原子重命名） | <0.1ms |
| INSERT | ~1ms |
| 合计 | **~4ms** |

100MB 视频时，`copyToTemp` 会变成主要成本（受磁盘吞吐限制），大约 0.3~1 秒（SSD）。

## 三、建素材：`POST /api/v1/assets`

```
客户端                    Controller              AssetServiceImpl          FileServiceImpl         MySQL
  │                          │                        │                        │                    │
  ├─ {kind:image,title,fileId,tags} →                 │                        │                    │
  │                          ├─ @Valid 校验（kind 白名单、title 非空）           │                    │
  │                          ├─ currentUserId()        │                        │                    │
  │                          ├─ create() ────────────→ │                        │                    │
  │                          │                        ├─ KIND_TEXT? 否           │                    │
  │                          │                        ├─ detail(userId,fileId) →│                    │

  │                          │                        │                        │  ← 归属校验        │
  │                          │                        │←─ FileVO ──────────────┤                    │
  │                          │                        ├─ categoryOf(mime)=image │                    │
  │                          │                        ├─ image == image ✓       │                    │
  │                          │                        ├─ setBytes/Width/...     │                    │
  │                          │                        ├─ coverUrl 为空 → 用文件 url                   │
  │                          │                        ├─ writeTags → '["纯色"]' │                    │
  │                          │                        ├─ writeJson(metadata)    │                    │
  │                          │                        ├─ INSERT t_asset ───────────────────────────→│
  │                          │                        ├─ toVO()                 │                    │

```

两次数据库往返（查文件 + 插素材），一次写入。

## 四、读内容：`GET /api/v1/files/{id}/content`

```
浏览器                  Filter 链               Controller                 Service              磁盘
  │  Range: bytes=0-99      │                      │                        │                  │
  ├────────────────────────→│                      │                        │                  │
  │                         ├─ JwtAuthenticationFilter（**必须带 token**）    │                  │
  │                         ├─────────────────────→│                        │                  │
  │                         │                      ├─ content() ───────────→│                  │
  │                         │                      │                        ├─ SELECT t_file →│
  │                         │                      │                        ├─ exists(key)? ─→│
  │                         │                      │←─ StoredContent ───────┤                  │
  │                         │                      ├─ parseRanges("bytes=0-99")                  │
  │                         │                      ├─ toResourceRegion()    │                  │
  │                         │←─ 206 + Content-Range┤                        │                  │
  │←─ 100 字节 ─────────────┤                      │                        │                  │
```

注意这条路径**必须带 token**，所以不能给 `<video src>` 直接用。`<video>` 用的是另一条：

```
GET /api/media/ab/abcdef...    → ResourceHandler → 直接读磁盘，不需要 token，原生支持 Range
```

## 五、删除链路的三次判断

```
DELETE /v1/files/{id}
    │
    ├─ ① 记录存在且属于我？          否 → 404 / 40430
    │
    ├─ ② 有素材引用它？              有 → 409 / 40930（把引用数告诉用户）
    │
    ├─ ③ 删记录之后，还有别的记录
    │     指向同一 sha256？          有 → 只删记录，磁盘留着
    │                                没有 → 删磁盘文件
    └─ 返回 200
```

三道判断的顺序不能换：②在③之前，因为"被引用"是业务约束；③是存储层约束。

## 六、异常路径都去了哪

| 异常 | 触发点 | 出口 |
| --- | --- | --- |
| `BizException(FILE_EMPTY)` | `copyToTemp` total==0 / `MultipartFile.isEmpty()` | `GlobalExceptionHandler` → 400 / 40022 |
| `BizException(UNSUPPORTED_FILE_TYPE)` | `categoryOf` 返回 null / `matchesMagic` 为 false | 400 / 40020 |
| `BizException(FILE_TOO_LARGE)` | `copyToTemp` 超限 | 400 / 40021 |
| `MaxUploadSizeExceededException` | Tomcat 层就拒了 | 专有 handler → 400 / 40021 |
| `IOException` | 磁盘满、权限不足 | catch 后转 `BizException(INTERNAL_ERROR)` → 500 |
| `NoSuchAlgorithmException` | 理论上不可能（SHA-256 是 JDK 必备） | `IllegalStateException` → 500 |
| `DuplicateKeyException` | 并发上传同一份内容 | **catch 后回查**，不是错误 |
| `HttpMessageNotReadableException` | base64 请求体格式错 | 400 / 40000 |
| `MethodArgumentTypeMismatchException` | `/files/abc` | 400 / 40000 |
| 临时文件残留 | 任何异常路径 | `finally` 里 `deleteIfExists` |

## 七、一个完整的 curl 时序（可直接对照日志看）

```bash
# 1. 登录
curl -X POST .../auth/login -d '{"account":"canvas_demo","password":"canvas1234"}'

# 2. 上传（记下 id 和 url）
curl -X POST .../files/upload -H "Authorization: Bearer $T" -F "file=@red.png"
# → { "id": "1857...", "url": "/api/media/9f/9f86d0...", "deduped": false }

# 3. 再传一次（秒传）
curl -X POST .../files/upload -H "Authorization: Bearer $T" -F "file=@red.png"
# → { "id": "1857...", "deduped": true }     ← id 相同

# 4. 建素材
curl -X POST .../assets -H "Authorization: Bearer $T" \
  -d '{"kind":"image","title":"红色方块","fileId":"1857...","tags":["纯色"]}'

# 5. 列表 + 标签
curl ".../assets?kind=image&tag=纯色" -H "Authorization: Bearer $T"
curl ".../assets/tags" -H "Authorization: Bearer $T"

# 6. 带 Range 取内容
curl -i .../files/1857.../content -H "Authorization: Bearer $T" -H "Range: bytes=0-9"
# → 206, Content-Range: bytes 0-9/1234

# 7. 删除保护
curl -X DELETE .../files/1857... -H "Authorization: Bearer $T"
# → 409 / 40930 文件已被 1 个素材引用
```

对应日志（同一个 traceId 串起来）：

```
[...a1b2c3...] FileRecordMapper.selectOne   Total: 1       ← 秒传查询
[...a1b2c3...] FileRecordMapper.insert      Updates: 1
[...d4e5f6...] FileRecordMapper.selectById  Total: 1       ← 建素材时查文件
[...d4e5f6...] AssetMapper.insert           Updates: 1
[...g7h8i9...] AssetMapper.selectCount      Total: 1       ← 删文件的引用检查
```

## 八、面试话术（一分钟版本）

> 文件这块我做了两张表：`t_file` 管字节，`t_asset` 管业务。
>
> 上传是流式的：64KB 缓冲循环读写，同一个循环里算 SHA-256、卡类型上限、写临时文件，所以内存占用和文件大小无关。临时文件放在存储根目录下的 `.tmp`，跟正式目录同一个文件系统，最后用 `ATOMIC_MOVE` 挪过去——跨盘的话原子移动会退化成复制，大文件慢一倍还可能留半截文件。
>
> 存储路径是内容寻址的：`{sha256前两位}/{sha256}`。这样同一份内容无论谁传、传几次，磁盘上只有一份；秒传就是查 `(user_id, sha256)` 命中就返回已有记录。代价是删除变成引用计数问题——删记录之后还要数一下全库还有没有别的记录指向同一个 sha，没有才删磁盘文件，否则会把别人的图删成裂图。
>
> 访问做了两条路径：`<img>`/`<video>` 带不了 Authorization 头，所以用一个静态映射 `/api/media/**` 公开只读，路径是 sha256 不可枚举；需要审计或下载原名的走 `/v1/files/{id}/content`，这条手动支持了 Range，返回 `ResourceRegion` 和 206，视频才能拖进度条。
>
> 校验上不信任客户端的 Content-Type：白名单之后还对图片做了魔数校验，把 exe 改成 png 会被拒；音视频的容器格式变体太多，我没有自己手写魔数——那种地方要严格就上 Tika。

追问一般会落在：**引用计数怎么保证并发安全**（答案是当前用 COUNT、多实例要加锁或 `ref_count` 列）、**为什么不用 MinIO**（抽象层已经留好，换实现不动 Service）、**怎么防止磁盘打满**（三层限制 + 清理接口 + 宽限期）。
