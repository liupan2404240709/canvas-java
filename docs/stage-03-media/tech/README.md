## 面试话术总纲

只准备一段话，背这段（覆盖 02~05、08、11 的核心）：

> 文件存储我做了一层 `FileStorage` 抽象，本地实现是内容寻址的：路径是 `{sha256前两位}/{sha256}`，前两位分片避免单目录文件过多。好处是同一份内容无论谁传、传几次磁盘只有一份，秒传就是拿 `(user_id, sha256)` 查一下命中就返回已有记录；代价是删除变成引用计数问题——删记录之后要数一下全库还有没有别的记录指向同一个 sha，没有才删磁盘文件，否则会把别人的图删成裂图。
>
> 上传是流式的：64KB 缓冲循环，同一个循环里累加大小（超限立刻中断）、更新 SHA-256 摘要、写临时文件，内存占用和文件大小无关。临时文件放在存储根目录的 `.tmp` 下，保证和正式目录同一个文件系统，最后 `ATOMIC_MOVE` 挪过去——跨盘的话原子移动会退化成复制加删除，大文件慢一倍，还可能留半截文件。
>
> 校验不信任客户端声明的 Content-Type：先过 MIME 白名单，再对图片做文件头魔数校验，把 exe 改名成 png 会被拒。音视频容器格式变体太多，我没有自己手写魔数判断——那种地方要么上 Tika，要么就老实承认只能挡随手改名。
>
> 访问做了两条路径：`<img>` 和 `<video>` 是浏览器发的资源请求，带不了 Authorization 头，所以用静态映射 `/api/media/**` 公开只读，路径是 sha256 不可枚举；需要审计的走 `/v1/files/{id}/content`，这条手动支持了 Range，返回 206 和 `Content-Range`，视频才能拖进度条。

追问时的补充点：

- 图片宽高在上传时用 `ImageReader` 只读文件头拿到，不用 `ImageIO.read`——那是整图解码，8000×8000 一张就 256MB，并发几个直接 OOM。
- 秒传省的是服务端存储和写库，**不省带宽**；要省带宽得先问后传（客户端算 sha 发 `POST /files/exists`），本项目没做，因为浏览器算 100MB 文件哈希很慢。
- 孤儿清理只处理"从未被任何素材引用过"的文件，且默认宽限期 24 小时——因为"上传"和"建素材"之间有人工间隔，宽限期 0 会删掉用户正在编辑的东西。
- 标签用 JSON 数组 + `JSON_CONTAINS` 过滤、`JSON_TABLE` 聚合。没建关联表是因为标签还是"弱结构"；哪天要做标签管理（重命名、颜色、合并）就必须拆表。
