# 04 出站探测与错误翻译

> 对应代码：`infra/channel/ChannelProbe.java`（243 行）、`config/ChannelHttpConfig.java`、`infra/net/OutboundHosts.java`

## 一、为什么"测试连通"和"拉模型"是同一个动作

OpenAI 兼容协议里没有 `ping`、没有 `health`。最轻的存活证明就是：

```
GET {base}/models
Authorization: Bearer sk-xxx
```

它同时回答了三个问题：网络通不通、Key 对不对、有哪些模型。

所以 `probe()` 一次返回四样东西：

```java
record Outcome(boolean ok, String message, List<String> models, int latencyMs, int httpStatus)
```

**如果拆成两个接口**，用户点"测试连接"通过、再点"拉取模型"失败，会非常困惑
（"刚才不是通了吗？"）。而且两次请求打同一个地址，纯属浪费。

## 二、超时：与提示词同步策略相反

```java
// ChannelHttpConfig
factory.setConnectTimeout((int) properties.getConnectTimeout().toMillis());  // 5s
factory.setReadTimeout((int) properties.getReadTimeout().toMillis());        // 15s
```

| | 提示词同步 | **渠道探测** |
| --- | --- | --- |
| 触发方 | 定时任务 | 用户点按钮 |
| 可接受的等待 | 20s 甚至更长 | 15s 已是耐心上限 |
| 慢的后果 | 后台任务延后 | 用户以为页面卡死 |

所以是两个**独立的 RestClient bean**，不共用。

### 2.1 为什么不能用 Spring 默认的 RestClient

Spring Boot 自动配置的 `RestClient.Builder` 底层用 `HttpURLConnection`，
**默认没有超时**（`connectTimeout = 0` 表示无限等待）。

后果很具体：用户填了一个被防火墙丢包的地址，请求线程会永久挂住。
Tomcat 默认 200 个工作线程，几十次这样的请求就能把服务打死。
而且这种故障在监控上表现为"线程池耗尽"，很难定位到具体是哪个功能。

**没有超时的 HTTP 客户端，是不允许上线的东西。**

### 2.2 为什么用 `SimpleClientHttpRequestFactory`

同步拉一个 JSON，没有背压、没有流式需求。引入 WebClient + Reactor 只会让调用链变复杂，
还得考虑"阻塞调用跑在哪个调度器上"。`HttpURLConnection` 足够，且零额外依赖。

## 三、响应体限长：必须流式判断

```java
private byte[] readLimited(InputStream in) throws IOException {
    long limit = properties.getMaxResponseBytes();   // 1MB
    ByteArrayOutputStream out = new ByteArrayOutputStream(BUFFER_SIZE);
    byte[] buffer = new byte[BUFFER_SIZE];
    long total = 0;
    int read;
    while ((read = in.read(buffer)) != -1) {
        total += read;
        if (total > limit) {
            throw new LimitExceededException("响应体超过 ... 上限，已中断");
        }
        out.write(buffer, 0, read);
    }
    return out.toByteArray();
}
```

**关键在"边读边判断"**。写成 `readAllBytes()` 再判断大小是错的——那时候内存已经被吃掉了，
一个返回 500MB 的"友好"网关就能把堆撑爆。

`/models` 正常只有几十 KB，1MB 已经是极宽松的上限。

### 3.1 一个编译期踩到的坑

`LimitExceededException` 最初继承 `IOException`，编译报错：

```
不应出现在 try 语句块中抛出的异常类型 LimitExceededException
```

原因：这段读取发生在 `RestClient.exchange(...)` 的 lambda 里，而那个函数式接口
**不允许抛受检异常**。既然传不出去，`catch (LimitExceededException e)` 就被判成不可达。

改成继承 `RuntimeException` 就解决了。这也说明一件事：**lambda 里的异常策略会反过来
约束你的异常类型设计**。

## 四、错误翻译：本阶段最重要的安全决策

```java
private String translate(int status) {
    return switch (status) {
        case 401, 403 -> "鉴权失败（HTTP " + status + "）：API Key 不正确，或该 Key 没有 /models 权限";
        case 404 -> "地址不对（HTTP 404）：这个地址下没有 /models 接口，请检查 Base URL 是否多写或漏写了 /v1";
        case 429 -> "请求过于频繁（HTTP 429）：稍后再试";
        case 500, 502, 503, 504 -> "上游服务异常（HTTP " + status + "），通常与本地配置无关，稍后再试";
        default -> "上游返回 HTTP " + status;
    };
}
```

### 4.1 为什么不把上游的 `error.message` 回显给用户

看起来"回显原文"对排查更有帮助，比如 `{"error":"Incorrect API key provided"}`。
但这条链路有一个特殊之处：**渠道地址允许指向内网**（本地 Ollama、公司内网网关都是正当场景）。

一旦回显响应体，这个接口就变成一个**能读内网 HTTP 响应的代理**：

```
攻击者：baseUrl = http://192.168.1.10:8080/admin/env
       → 探测 → 把内网接口的响应体原样返回给他
```

所以 `allow-private-host` 可以开（为了本地模型），但**响应体必须一律不回显**。

### 4.2 那用户怎么排查？

状态码 + 一句人话已经覆盖 95% 的情况：

| 状态码 | 用户实际遇到的问题 |
| --- | --- |
| 401 | Key 粘错了 / 粘了别人的 / 没开通该模型权限 |
| 404 | 地址多了 `/v1` 或少了 `/v1`、把控制台地址当接口地址 |
| 429 | 免费额度用完了 |
| 5xx | 上游自己挂了 |

这三个结论都能从状态码直接推出来，不需要响应体原文。
**"能定位问题"和"能读到上游原文"是两件事，我们要的是前者。**

## 五、解析失败要报错，不能当"没有模型"

```java
try {
    root = objectMapper.readTree(body);
} catch (Exception e) {
    return Outcome.fail("地址返回的不是 JSON，请确认填的是接口地址而不是控制台网页地址", 200);
}
```

这是**最常见的配置错误**：把 `https://bailian.console.aliyun.com` 粘进 Base URL。
那是个网页，返回 200 + HTML。

如果只按"解析出 0 个模型"处理，用户会看到"连接成功，发现 0 个模型"，
然后以为自己配对了、只是账号没模型——排查方向完全错。

所以：**能解析出 JSON 结构才算连通**。

### 5.1 三种响应外壳都要认

```java
if (root.isArray())                    { array = root; }            // 少数网关直接返回数组
else if (gemini && root.has("models")) { array = root.get("models"); geminiPrefix = true; }
else if (root.has("data"))             { array = root.get("data"); } // OpenAI 标准
else if (root.has("models"))           { array = root.get("models"); geminiPrefix = true; }
```

取值也做了兜底：OpenAI 用 `id`，Gemini 用 `name`，有的网关两者都有 → 先取 `id` 再退回 `name`。

### 5.2 Gemini 的 `models/` 前缀必须剥掉

```java
if (geminiPrefix && name.startsWith("models/")) {
    name = name.substring(GEMINI_MODEL_PREFIX.length());
}
```

Gemini 返回的是 `{"name": "models/gemini-2.0-flash"}`。如果原样存进库，
后续拼 URL 会变成 `/models/models/gemini-2.0-flash`，直接 404。

这个前缀是**协议差异**，不是模型名的一部分——所以在入口就归一化掉，
让库里存的永远是"裸模型名"。

## 六、限流与截断

```java
if (names.size() >= properties.getMaxModels()) break;   // 默认 500
```

用 `LinkedHashSet` 收集：既去重又保留上游顺序（`HashSet` 会打乱，用户看到的顺序就随机了）。

截断的必要性：某些聚合平台（硅基流动、One-API）会返回几百上千个模型。
全部塞给前端下拉框，用户体验是灾难（滚不到底、搜不准）。
500 个已经远超正常使用量。

## 七、主机安全校验：默认允许内网，但要能关

```java
if (!OutboundHosts.allowed(uri, properties.isAllowPrivateHost())) {
    return Outcome.fail("出于安全限制，不允许访问内网/回环地址", 0);
}
```

### 7.1 为什么默认 `true`

`http://127.0.0.1:11434/v1`（本地 Ollama）、`http://192.168.1.5:8000/v1`（公司内网 vLLM）
是这个功能的核心场景。默认拒绝等于砍掉"自建模型"这条路。

### 7.2 那 SSRF 怎么办

风险确实存在，但被"不回显响应体"压到了很低：

- 攻击者能验证"某个内网端口上有没有一个 OpenAI 兼容的 `/models`"；
- 拿不到响应内容；
- 不跟随重定向到别的地址；
- 错误信息只有状态码。

要彻底防死只能做**域名白名单**，那样本地模型也就没了。这是明示的取舍，
配置文件里写清了"服务对外暴露时改成 false"。

### 7.3 为什么把这段逻辑抽到 `OutboundHosts`

原本这段代码在阶段 4 的 `PromptUrls.hostAllowed` 里。阶段 5 需要同样的判断，
但**策略相反**（提示词默认拒绝内网，渠道默认允许）。

安全代码复制两份 = 以后只修一处。所以抽成 `infra/net/OutboundHosts.allowed(uri, allowPrivate)`，
差异通过参数表达；`PromptUrls.hostAllowed` 保留原签名、内部委托，阶段 4 的调用点一行没改。

## 八、面试考察点

**Q1：为什么把"测试连通"和"拉模型"合成一个接口？**
A：OpenAI 兼容端点没有 ping 接口，`GET /models` 就是最轻的存活证明。拆成两个接口会出现
"测试通过、拉模型失败"的困惑，而且两次请求打同一个地址纯属浪费。

**Q2：探测失败为什么返回 200 而不是 4xx/5xx？**
A："连不上"是业务答案，不是请求错误。返 500 会让前端每个调用点都写 try/catch，
还会污染监控的错误率（用户填错 Key 不该算服务端故障）。

**Q3：为什么不回显上游的错误信息？**
A：因为渠道地址允许指向内网（本地 Ollama 是正当场景）。回显响应体等于把这个接口
变成能读内网 HTTP 响应的代理。状态码 + 人话翻译已经能覆盖 95% 的排查场景。

**Q4：响应体限长为什么必须流式？**
A：`readAllBytes()` 再判断大小时，内存已经被吃掉了。必须边读边累加，超限立刻中断。

**Q5：如果用户把控制台网页地址填成了 Base URL，你的代码会怎样？**
A：对方返回 200 + HTML，JSON 解析失败，返回 `ok=false` + "地址返回的不是 JSON，
请确认填的是接口地址而不是控制台网页地址"。**不能**当成"连通但 0 个模型"，
否则用户会往错误方向排查。

**Q6：Gemini 的模型名为什么要特殊处理？**
A：它返回 `models/gemini-2.0-flash`，前缀是协议的一部分，不是模型名。原样存库会让后续
拼 URL 变成 `/models/models/...`。所以在入口剥掉，库里永远存裸名。

**Q7：为什么不用 Spring 默认的 RestClient？**
A：它默认**没有超时**（`connectTimeout=0` 表示无限等）。一个丢包的域名会永久占住
Tomcat 线程，几十次就能打死服务，而且监控上只表现为"线程池耗尽"，很难定位。
