## 三条主线

这 12 篇其实在反复讲三件事。

### 主线一：密钥只在必要的地方出现

```
用户输入 ──► 加密落库（v1:…）──► 列表只回 hint ──► 调用时后端解密
                │                    │                    │
            明文只活一次          列表不碰密文        明文不出服务端
```

对应 01（为什么 hint 单独一列）、02（怎么加解密）、09（谁能读到）。

### 主线二：出站请求必须有边界

| 边界 | 在哪 |
| --- | --- |
| 超时 | `ChannelHttpConfig`（5s / 15s） |
| 响应体大小 | `ChannelProbe#readLimited`（1MB，流式判断） |
| 主机白名单 | `OutboundHosts`（可关，默认开） |
| 错误信息 | `translate()`（只给状态码，不给响应体） |

对应 03、04。

### 主线三：整体保存 ≠ 全删全插

界面是一次提交整份表单，但落库时按名字做差量。理由是**主键要稳定**——
阶段 6 的生成任务会引用模型 id，全删全插会让所有引用悬空。
这和阶段 2 画布快照"整份替换"是相反的选择，因为两者的主键语义不同。

对应 06、07。

## 和各阶段的关系

| 阶段 | 关系 |
| --- | --- |
| 阶段 1（认证） | `SecurityUtils.currentUserId()` 提供归属；本阶段所有方法第一参数都是它 |
| 阶段 4（提示词） | `OutboundHosts` 从 `PromptUrls` 抽出来共用；两处策略相反（默认拒绝 / 默认允许内网） |

## 怎么用这份文档

- **准备面试**：直接看每篇末尾的「面试考察点」，答不上来再回头读正文。
- **要改代码**：先看 12 的链路图，确认改动落在哪一层，再看对应那一篇的"为什么"。
- **code review**：重点看 02（密钥）、04（出站）、06（差量）——这三处的错误最隐蔽。
