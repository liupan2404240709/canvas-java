# 11 测试控制台与前端契约

> 对应代码：`static/demo/index.html`（新增「渠道与模型」页签）、`static/demo/app.js`（1411 → 1948 行）

## 一、控制台的定位

它**不是**产品前端，是"接口自测与演示"面板：

- 只服务一个演示账号（`demo` / `demo123456`）；
- 不做路由、不做状态管理、不做错误兜底设计；
- 每个页签对应一个阶段的接口集合，用来验证后端在真实浏览器里的行为。

正式前端对接是阶段 9，缺口清单在 `docs/frontend-integration.md`。

所以这里的取舍是：**能验证接口语义就行，不为好看写复杂交互**。

## 三、数据加载：三个请求并行

```js
async function loadChannels() {
    const [list, presets, models] = await Promise.all([
        api("/channels", { silent: true }),
        api("/channels/presets", { silent: true }),
        api("/models", { silent: true }),
    ]);
    ...
}
```

三个接口互不依赖，用 `Promise.all` 并行。`silent: true` 表示不打进「接口流水」
（否则每次刷新页面会多三条噪音），但仍会在失败时抛异常。

`loadChannels` 被挂在 `loadAll()` 里，和画布/素材/提示词一起加载。
登录后一次性把五个页签的数据都拉好，切页签时不再等。

## 四、"预设填充"的三个细节

```js
function applyPreset() {
    const preset = state.channels.presets.find((p) => p.key === $("presetSelect").value);
    $("cfName").value = preset.name;
    $("cfBaseUrl").value = preset.baseUrl;
    $("cfFormat").value = preset.apiFormat;
    $("cfModels").value = preset.models.map((m) => m.name).join(", ");
    showChannelForm(true);
    $("cfStatus").textContent = preset.note || "";
}
```

### 4.1 不清空 API Key 输入框

用户可能已经粘好 Key，再换一个预设。清空它意味着重新粘一次——
而且 Key 粘贴是最烦的一步。

### 4.2 预设的 `note` 显示在状态栏

方舟那条"文本模型 ID 带日期后缀，请从控制台复制"就在这里显示。
用户选完预设第一眼看到的就是它，而不是等到出错了才去翻文档。

### 4.3 下拉框重建时保留选中值

```js
const current = select.value;
select.innerHTML = '<option value="">…</option>';
for (const preset of c.presets) select.append(...);
select.value = current;
```

因为 `renderChannels()` 会在每次刷新时重建整个 DOM（包括下拉框）。
不保留 `value` 的话，用户选了预设、点一次"测试"、下拉框就跳回"请选择"。

**这是"全量重渲染"模式的通病**：状态存在 DOM 里就会被冲掉，要手动搬运。

## 五、"先测后存"是这一阶段最值得抄的交互

```
填地址 + Key  ──[探测]──►  通：显示 "通 · 3 个模型 · 312ms"，并自动填模型输入框
                        └►  不通：显示 "不通：鉴权失败（HTTP 401）…"
       │
       └──[保存]──► POST /v1/channels
```

关键在探测成功后**顺手把模型名填进去**：

```js
if (names.length && !$("cfModels").value.trim()) {
    $("cfModels").value = names.join(", ");
}
```

条件 `!value.trim()` 很重要：只有用户**没填**的时候才自动填，
不覆盖他已经输入的内容。

这个设计让"新建一个渠道"从"手敲一堆模型名"变成"点两下"。

### 5.1 为什么探测用 `POST /channels/probe` 而不是先保存再测

先保存再测的问题：填错了要删掉重来（`DELETE` 一次），而且库里会留下一条
"永远不通"的记录。探测接口不落库，改了重试零成本。

这也解释了为什么 `probe` 要支持"带 `channelKey` 但不带 `apiKey`"：
测试已存渠道时，前端拿不到明文 Key（接口只回 hint），所以要让后端自己去解密。

## 六、前端只能用 hint，这是个硬约束

控制台的渠道卡片显示：

```js
`${channel.apiKeyHint} · ${channel.models.length} 个模型`
```

前端**没有任何途径**拿到明文 Key。这带来两个连锁设计：

1. "编辑渠道"不能预填 Key 输入框 → 只能用占位符提示"留空表示不修改"；
2. "测试已存渠道"不能由前端拼请求头 → 必须由后端用库里的密文解密后发请求。

**约束会传导到接口形态上**。如果当初为了"方便"让 `GET /channels` 返回明文，
上面两处都会变简单，但整个系统的安全边界就没了。

## 七、右侧模型面板为什么要自己做筛选

```js
const items = c.models.filter((m) => c.cap === "all" || m.capability === c.cap);
```

后端 `/v1/models?capability=image` 支持服务端过滤，但控制台这里做的是**客户端过滤**。

为什么：`state.channels.models` 已经全量拿到了（通常就几十条），
在切换能力页签时不该再发请求——那会让点击有 100ms 的延迟感。

**这是"数据量小就客户端过滤"的典型场景**。如果模型有几千条，
就必须改回服务端过滤 + 分页。

## 八、卡片状态用色和图标表达

| 状态 | 表现 |
| --- | --- |
| 渠道启用 | 正常不透明 |
| 渠道停用 | `src-card off` → `opacity: .5` |
| 从未测试 | 无标签 |
| 测试通过 | 标签「通」 |
| 测试失败 | 标签「不通」+ 红色错误行 |

`lastTestOk` 是 `true` / `false` / **`undefined`**（后端 null 时字段不出现），
所以判断必须写 `=== true` / `=== false`，不能写 `if (x)`：

```js
if (channel.lastTestOk === true) title.append(el("span", { class: "tag-mini", text: "通" }));
if (channel.lastTestOk === false) title.append(el("span", { class: "tag-mini", text: "不通" }));
```

`if (x)` 在没有这个字段时也是 false，看起来"能用"，但 `x === false` 时同样为 false，
会把"测试失败"当成"没测过"——状态显示错误但不会报错，最难查。

## 九、静态资源要同步到 target

控制台的 `app.js` / `index.html` 是**编译期拷贝**进 `target/classes/static/demo/` 的。
后端已经用 `mvn spring-boot:run` 跑着的时候改这两个文件，**不重启不生效**。

改完要么重启，要么手动同步：

```powershell
cp D:\project\canvas-java\src\main\resources\static\demo\* `
   D:\project\canvas-java\target\classes\static\demo\
```

这是控制台开发阶段最常见的一次"我明明改了啊"。

## 十、面试考察点

**Q1：为什么做"先测后存"，而不是保存后再测？**
A：填错就要删掉重来，库里还会留一条永远不通的记录。探测接口（`POST /channels/probe`）
不落库，改完重试零成本。而且探测成功可以顺手把上游模型名填进表单，把"手敲模型名"变成"点两下"。

**Q2：测试已存渠道时，前端没有明文 Key 怎么办？**
A：让后端解密。`POST /channels/{key}/test` 不需要前端传 Key，
`probe` 也支持"带 channelKey 但不带 apiKey，用库里已存的密文"。
这是"前端只能看到 hint"这个约束传导出来的接口设计。

**Q3：为什么切换能力页签用客户端过滤？**
A：数据已经全量在内存里（几十条），再发请求会让点击有延迟感。
如果模型有几千条，就必须改回服务端过滤 + 分页。这是随数据量变化的取舍。

**Q4：`lastTestOk` 为什么不能用 `if (x)` 判断？**
A：它是三态（true / false / 字段不存在）。`if (x)` 对 false 和 undefined 都是假，
会把"测试失败"错误地当成"从未测试"。必须显式写 `=== true` / `=== false`。

**Q5：控制台为什么不复用产品前端？**
A：产品前端要接的是完整链路（登录、画布、生成任务），而控制台的目的是
"单独验证某组接口"。混在一起会导致改后端时要连带调前端构建。
阶段 9 再做正式对接，缺口清单见 `frontend-integration.md`。
